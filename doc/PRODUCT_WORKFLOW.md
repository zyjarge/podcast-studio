# Podcast Studio 产品应用场景与工作流

> 版本: 1.0 | 更新日期: 2026-10-13
> 本文基于当前代码实现梳理（frontend/ + backend/），与 `doc/DESIGN.md`（早期 PRD）存在差异处以本文为准；尚未实现的能力统一标注为「规划中」或「半成品」。

---

## 一、产品定位

**Podcast Studio** 是一个 AI 播客创作工作站：从 RSS 新闻源采集科技热点，由大模型（DeepSeek）生成**双主播对谈逐字稿**，再经 MiniMax TTS 合成双音色语音，最终输出一期完整可听的播客节目。

**节目形态**（由 `backend/app/services/prompts.yaml` 定义）：

- 节目名：《科技双响炮》，单期 15–20 分钟，约 4000–5000 字
- 固定开场白："科技双响炮，焦点早知道，每天通勤路上，陪你准时开炮！"（由代码拼接，不经过 LLM）
- 双主播人设：
  - **彪悍罗**：犀利、幽默、敢说真话，负责尖锐提问与吐槽（音色 `luoyonghao2`）
  - **OK王**：专业、理性、重数据，从产品/技术角度补充分析（音色 `wangziru_latest`）

**目标用户**：个人博主、内容创作者、媒体从业者——希望以较低成本把每日科技资讯转成一档有"人味"的对谈播客。

## 二、应用场景

### 场景 1：日更科技评说播客（核心场景）

用户每天早上打开系统，抓取各 RSS 源最新新闻，借助 AI 评分快速挑出 5–10 条有价值的素材，一键生成本期逐字稿，稍作精调后合成音频，当天即可产出一期通勤时段收听的对谈节目。

### 场景 2：人工精编的精品节目制作

对质量要求高的用户走"精编"路线：逐条审阅新闻、为每条新闻写**编辑备注**（给 LLM 的角度指令，如"重点聊对开发者的影响"）、撰写**节目备注**（本期整体基调），AI 成稿后在页面内逐字修改，再合成音频。

### 场景 3：半自动批量生产（半成品）

系统在数据模型和 API 层面预留了自动化能力：RSS 源可标记 `auto_mode`、存在批量生成（batch-generate / generate-all）端点。但目前前端"自动模式"切换仅为主观感切换（Sidebar 上的模式按钮不改变任何实际行为），定时任务 tab 也未实现，**全自动流水线属于规划中**。

### 场景 4：多源内容聚合与选题辅助

即使用户自己写稿，系统也可作为选题工具：多 RSS 源聚合 + 每条新闻的 AI 评分（权威性/时效性/深度三维度，折算为 5 星展示）+ 关键词提取，帮助编辑快速判断哪些新闻值得做。

## 三、核心概念与状态机

### 3.1 数据模型

| 实体 | 说明 | 关键字段 |
|---|---|---|
| **Episode（节目）** | 一期播客 | title、status、script（整期逐字稿）、audio_url、scheduled_date、intro_template/outro_template/script_prompt（⚠️ 仅存未用） |
| **News（新闻）** | RSS 抓取的全局新闻池条目 | title、source、url、summary、content、keywords、score 及三维度子分 |
| **EpisodeNews（节目-新闻关联）** | 新闻加入节目后的实例 | order、status、prompt（单条自定义提示词）、notes（编辑备注）、script、audio_url、deleted_at（软删除） |
| **RSSSource（RSS 源）** | 采集来源配置 | name、url、enabled、auto_mode、authority_score（⚠️ 仅存未用） |

### 3.2 状态流转

**节目状态**：`draft`（新建）→ `editing`（处理中）→ `published`（已发布）

- ⚠️ 目前没有"发布"操作入口（前后端均无把状态置为 published 的 UI；`published_at` 字段从不写入），发布流程待补。

**单条新闻状态**：`pending` → `generating` → `script_done` → `audio_done`，失败进入 `error`

**音频生成阶段**（整期音频，前端进度条轮询展示）：
`idle → starting → parsing → submitting → processing → downloading → merging → done / error`

## 四、端到端主工作流（已实现并验证的成品路径）

这是当前**唯一完整走通**的生产路径，也是产品的主动脉：

```
配置 → 采集 → 建节目 → 选料 → 整理 → 生成逐字稿 → 人工精调 → 合成音频 → 试听/重制
```

### 第 0 步：初始配置（一次性）

入口：侧边栏 → 设置页

1. **API 配置 tab**：填写 DeepSeek API Key（脚本生成）和 MiniMax API Key（语音合成），保存后写入 env 文件。页面会实际调用两家接口验证 key 可用性并显示连接状态徽章。
2. **RSS 源 tab**：添加 RSS 源——粘贴 URL 后可点"从 URL 解析标题"自动填名称；每个源可独立启用/禁用、可标记"自动模式"。
3. （可选）**提示词配置 tab**：自定义系统提示词。⚠️ 当前该配置保存后**不影响实际生成**（后端实际消费的是 `prompts.yaml`，见 GitHub Issue #24）。

### 第 1 步：采集新闻

两条触发路径：

- 新闻池页 → "抓取新闻"按钮（可只抓选中的来源）
- 节目详情页 → 添加新闻弹窗内 → "抓取最新"

后端行为（`POST /api/v1/news/fetch`）：对所有启用的 RSS 源各抓取最新 20 条，按 URL 去重；**新条目入库时立即完成 AI 评分**（评分机制见第七节），单个源失败不影响其他源。

### 第 2 步：创建节目

入口：首页（Dashboard 日历视图）→ "新建节目" → 填标题 + 预计播出日期 → "创建并编辑"，自动进入节目详情页。节目按 `scheduled_date` 落在日历对应格子上。

### 第 3 步：选料（把新闻加入节目）

两条路径：

- **a. 节目详情页** → 左侧"添加新闻"弹窗：按来源 Tab / 标题搜索筛选，卡片显示来源、AI 评分星级、日期；点选进入右侧"购物车"，实时统计条数/总字数/**预估时长**（按 150 字/分钟换算），确认后批量添加。
- **b. 新闻池页**：按来源分区的卡片网格，支持来源多选筛选、搜索、评分档位过滤（60+/75+/90+）；可点开详情弹窗阅读全文；勾选后"添加到节目"并选择目标节目。

### 第 4 步：整理素材

在节目详情页左栏：

- **拖拽排序**：调整新闻在对谈中的出场顺序（⚠️ 当前仅前端生效，刷新后还原，后端 reorder 接口已存在但未接线）
- **写备注**：展开某条新闻可填编辑备注，作为该条新闻的角度指令随素材一起发给 LLM（持久化到后端）
- **删除**：两步确认后软删除，进入回收站（⚠️ 回收站的后端接口齐全，前端暂无入口）

### 第 5 步：生成本期逐字稿

在详情页右栏"逐字稿"区：

1. （可选）先在"节目备注"区填写本期整体要求（如"今天是高考日，开场可以提一句"）。⚠️ 节目备注不持久化，仅本次会话有效
2. 点击"生成逐字稿"→ 后端汇总所有未删除新闻的标题/正文/编辑备注 + 节目备注，一次性调用 LLM 成稿（同步请求，约等待数十秒）
3. 生成完成后文本前自动拼接固定开场白，存入 `episode.script`；刷新页面会从数据库恢复

### 第 6 步：人工精调

点击"编辑"进入整篇逐字稿的 inline 编辑（textarea），修改后保存。适合修正事实错误、调整段子、删减冗长段落。

### 第 7 步：合成音频

点击"生成音频"→ 后端启动后台任务，前端每 2 秒轮询进度（阶段 + 百分比）。完成后出现播放器，可直接在页面试听。不满意可"删除音频"后重新生成。合成流水线细节见第六节。

### 第 8 步：发布（待补）

音频文件可通过 `/audio/{episode_id}/episode_{id}.mp3` 访问/下载。⚠️ 将节目标记为"已发布"的完整流程（状态置位、发布时间、导出/分发）目前未实现。

## 六、音频合成流水线（技术流程）

整期音频由后台任务完成（`POST /episodes/{id}/generate-episode-audio` 立即返回，进度通过 `GET /audio-progress` 轮询）：

1. **解析**：按 `**彪悍罗：**` / `**OK王：**` 标签把逐字稿切成对话片段（兼容旧角色名"罗永浩/王自如"）
2. **提交**：按角色分配音色，调用 MiniMax `t2a_async_v2` 异步接口，并发上限 5；模型与语速/音量/音调参数实时读取 env（默认 `speech-2.8-hd`、语速 0.9）
3. **轮询**：每 2 秒查询各任务状态，单任务最长等待 10 分钟
4. **下载**：逐段保存为 `data/audio/episode_{id}/splits/part_NNN.mp3`
5. **合并**：ffmpeg concat 重编码（44.1kHz 立体声）合成 `episode_{id}.mp3`，写回 `episode.audio_url`

⚠️ 已知边界：开场白只有文字、不会被合成进音频（TTS 只认 speaker 标签行）；进度保存在单进程内存中，重启即丢；后台任务挂在请求生命周期上，进程重启会中断生成（见 Issue #8/#9）。

## 七、AI 新闻评分机制

纯规则打分（不消耗 LLM），三维度加权：**权威性 0.35 + 时效性 0.35 + 深度 0.30**

- **权威性**：域名白名单分档（36kr/虎嗅 90+、wallstreetcn 85、微博 50、未知来源 40）
- **时效性**：按距抓取时间的间隔分档（≤1 小时 100 分 → >72 小时 10 分）
- **深度**：按正文字数分档（≥3000 字 100 分 → <200 字 15 分）

评分在新闻入库时自动完成；也可通过 `POST /news/score-all` 对最近新闻批量重算（⚠️ 前端未接此入口）。前端以 5 星形式展示（≥90 分为五星），新闻池支持按 60+/75+/90+ 档位过滤。

## 八、Prompt 与角色体系

实际生效的 prompt 全部在 `backend/app/services/prompts.yaml`（启动时加载一次）：

| 配置项 | 用途 |
|---|---|
| `podcast_system_prompt` | 整期生成的系统提示：双人交替、彪悍罗先开口、互称"老罗/自如"、每人 2–5 句、严格 `**彪悍罗：**` 输出格式 |
| `podcast_user_template` | 用户提示模板：填入新闻素材，要求自然引用新闻（禁止"新闻15"式编号）、禁止额外加粗、年份写中文数字 |
| `luo_system_prompt` / `ziru_system_prompt` | 单角色风格指纹（口头禅、语言习惯），当前主要供单条生成路径使用 |
| `intro_text` | 固定开场白，代码拼接、不过 LLM |

⚠️ 设置页的"提示词配置"写入 env 的 `SCRIPT_PROMPT`，该键没有任何服务消费（Issue #24）；单条新闻的自定义 prompt 字段（EpisodeNews.prompt）同样仅存未用。

## 九、当前实现边界速览

修改本文档前建议先读这一节——以下是与"表面承诺"不符的实际状态，多数已登记为 GitHub Issue：

- **唯一可靠的成品路径**是第四节的整期流程；单条新闻的脚本生成正常，但**单条音频生成链路是坏的**（内部调用了未实现的接口，必然失败）
- 拖拽排序不持久化；节目备注（episode_notes）不持久化；回收站、批量生成、AI 重评分后端有接口但前端未接
- 无"发布"操作入口；`published_at` 从不写入
- ScriptEditor / AudioStudio / Integration 为纯 mock 演示页，无导航入口
- 设置页保存 DeepSeek key 后需重启后端生效（客户端是启动时构造的单例）；MiniMax 参数即时生效
- 音频进度为单进程内存态；后台音频任务无断点恢复能力
- 相关 Issue：#7–#15、#17–#21、#23、#24

## 十、与原始技术愿景的关系

`AGENTS.md` 与 `mvp/` 目录保留了最初的 LangGraph + Gemini 方案原型（Map-Reduce 拓扑：Fetch → Filter → Crawl & Summarize → Planner → Writer → TTS）。正式版出于成本与复杂度考虑改用了 **DeepSeek 单次成稿 + 同步 API** 的简化架构，`mvp/` 目前仅作参考与素材（音色文件、语音克隆脚本）保留，不参与生产链路。
