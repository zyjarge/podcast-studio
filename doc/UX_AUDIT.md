# Podcast Studio UX 审计报告

> 版本: 1.0 | 审计日期: 2026-10-13
> 方法：基于代码走查（非真实用户测试），覆盖前端 8 个页面 + 后端接口行为。
> 本文只列**体验层**问题；纯代码缺陷请见 GitHub Issues。改进后的目标形态见 `doc/UX_DESIGN.md`。

---

## P0 阻断性（用户操作落空或被骗）

| # | 问题 | 位置 | 用户视角的影响 |
|---|---|---|---|
| 1 | 拖拽排序不保存，刷新后还原 | `EpisodeDetail.jsx:109`（TODO 注释） | 用户花时间排好的顺序凭空消失，信任感崩塌 |
| 2 | 单条新闻的"生成音频"链路必失败（后端调了未实现接口） | `podcast.py:171` → `tts.py:155` | 一旦 UI 暴露此入口就是死路；当前 UI 未暴露，属隐患 |
| 3 | 提示词配置保存后不生效（后端消费的是 prompts.yaml） | Settings 提示词 tab，Issue #24 | 用户改了 prompt、看到"已保存"，生成结果毫无变化 |
| 4 | 设置页顶部"保存设置"对非 API tab 只播放画、不保存任何东西 | `Settings.jsx:148-163` | 用户以为保存了，实际没有 |
| 5 | mock 页面（ScriptEditor/AudioStudio/Integration）可通过 URL 访问 | `App.jsx:22-32`，Issue #18 | 用户撞进去看到以假乱真的假数据页面 |
| 6 | 流程无闭环：没有"发布"操作，节目永远停在 draft/editing | 全站无入口；`published_at` 从不写入 | 完成音频后不知道"做完了没有"，状态机形同虚设 |
| 7 | "生成逐字稿"同步等待数十秒，除按钮 loading 外无任何说明 | `EpisodeDetail.jsx:306` | 用户不确定是卡死了还是在生成，可能重复点击或离开 |

## P1 严重（反馈缺失或误导）

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| 8 | 成功/失败反馈用浏览器原生 alert/confirm | 如 NewsPool 添加成功 alert | 打断操作、样式割裂、无法提供"撤销" |
| 9 | 节目备注刷新即丢（只存在 React state） | `EpisodeDetail.jsx` episode_notes | 用户写给 AI 的本期要求，刷新后没了 |
| 10 | 进度条是假数据（`getProgress()` 硬编码返回 0） | `EpisodeList.jsx:130-132` | 展示信息与事实不符，不如没有 |
| 11 | 死 UI 控件：排序下拉框无效、minScore/dateRange 筛选无控件 | `NewsPool.jsx:190-201`、`EpisodeDetail.jsx:53-57` | 点了没反应，用户怀疑系统坏了 |
| 12 | DeepSeek key 保存后需重启后端才生效，仅 alert 一句话 | `Settings.jsx` API tab | 用户改完 key 立刻试用 → 失败，原因不明 |
| 13 | 抓取新闻多源串行无进度，只等最后一次性刷新 | NewsPool / 添加新闻弹窗 | 源多时要干等，不知道抓了没有 |
| 14 | 网络/服务异常只 console.error，界面无任何提示 | 多处（如 EpisodeDetail 抓取） | "点了按钮没反应"类困惑的最大来源 |
| 15 | 生成失败进入 error 态后无重试入口、无原因说明 | EpisodeDetail 新闻卡片 | 失败即死局 |

## P2 优化（不一致与小摩擦）

| # | 问题 | 说明 |
|---|---|---|
| 16 | 自动模式切换是纯装饰 | 已在 UX_DESIGN.md 决策移除（顺带解决 Issue #20） |
| 17 | EpisodeList 与 Dashboard 功能重叠且无导航入口 | 建议合并（保留批量删除能力） |
| 18 | "已发布"节目的播放按钮无 onClick | 装饰性按钮 |
| 19 | 空状态缺失或只有干巴巴的文字 | 无新闻/无节目/筛选无结果处需要引导式空态 |
| 20 | 新闻状态 audio_done 在整期流程下永远不会出现 | 状态语义与实际流程脱节，需重新定义 |
| 21 | 评分只有星级，鼠标悬停无三维度（权威性/时效性/深度）解释 | 用户不知道为什么这条新闻 4 星 |
| 22 | 新闻加入节目后，新闻池里无"已在节目中"标识 | 可能重复添加同一节目（后端会跳过，但用户不知情） |
| 23 | 侧边栏"节目列表"指向日历页，命名与内容不符 | 改名为"节目"或"日历" |

## 改进路线图

**第一批（止损，1 天内）**：#1 接 reorder API · #4 移除假保存按钮 · #5 移除 mock 路由 · #7 加生成中提示 · #11 删除死控件 · #16 移除自动模式 · #23 改名

**第二批（闭环，2-3 天）**：#6 发布流程 · #8 Toast 体系 · #9 备注持久化 · #10 真进度或移除 · #14 统一网络错误提示 · #15 失败重试

**第三批（提效与打磨）**：#3 提示词链路修复（依赖 Issue #24 决策）· #13 抓取进度 · #19 空状态体系 · #21 评分解释 · #22 重复添加标识

> 注：#2 建议短期在 UI 层永远不暴露单条音频入口（保持"整期合成"唯一路径），长期再决定是否修复后端链路。
