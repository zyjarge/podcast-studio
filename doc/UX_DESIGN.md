# Podcast Studio UX 设计文档

> 版本: 1.0 | 更新日期: 2026-10-13
> 配套文档: `doc/PRODUCT_WORKFLOW.md`（产品流程现状）、`doc/UX_AUDIT.md`（现状问题清单）、`doc/UX_COPY.md`（文案体系）
> 本文描述**目标形态**的 UX 设计，核心决策：**移除自动模式，只保留一条精编主线**。

---

## 一、设计目标与原则

### 1.1 设计目标

**日常产出一期节目，从打开系统到试听完成，操作不超过 6 步、主动操作时间不超过 5 分钟**（LLM/TTS 等待时间不计，但等待期间必须有明确反馈）。

### 1.2 四条设计原则

| 原则 | 含义 | 落地体现 |
|---|---|---|
| **一条主线** | 全站只有一条核心动线：选料 → 写稿 → 配音 → 完成 | 砍掉自动模式、mock 页、重复入口；任何页面离主线不超过 1 次点击 |
| **少跳页** | 能在一个页面完成的，不让用户跳转 | 选料、备注、写稿、精调、配音全部在 EpisodeDetail 完成 |
| **状态可见** | 任何耗时操作都有进度；任何数据都有来源说明 | 生成进度条、Toast 反馈、"已从数据库恢复"提示 |
| **操作可逆** | 破坏性操作可确认、可挽回 | 删除软处理（回收站）、两步确认、Toast 提供撤销窗口 |

---

## 二、关键决策：移除自动模式

**背景**：自动模式场景不成熟，且当前实现中模式切换是纯 UI 装饰（`Sidebar` 切换 `currentMode`，但 `EpisodeDetail` 从未接收该 prop，`Dashboard` 接收了也不用——见 Issue #20）。保留它只会让用户产生"点了没反应"的困惑。

**设计要求**：

1. 移除 Sidebar 的"精编/自动"模式切换器（`Sidebar.jsx:44-72`）
2. 移除 `App.jsx` 的 `currentMode` state 及所有 prop 传递
3. RSS 源的 `auto_mode` 开关从设置页 UI 隐藏（后端字段暂留，标注待清理）
4. Settings 的"定时任务"tab 一并移除（它属于自动模式语境）
5. 文案层面不再出现"模式"概念——系统就是"手动精编"一种用法

**收益**：导航更干净，消除一个"看似能点实则无效"的信任损耗点。

## 三、信息架构

### 3.1 导航模型（收敛后）

```
┌─────────────────────────────────────────────┐
│ 侧边栏（固定 256px）                          │
│                                             │
│  🎙️ Podcast Studio                         │
│                                             │
│  📅 节目          → /         (Dashboard)   │
│  📰 新闻池        → /news-pool              │
│                                             │
│  ─────────────                              │
│  ⚙️ 设置          → /settings               │
└─────────────────────────────────────────────┘
```

- **只保留两个主导航 + 设置**，与现状 Sidebar 一致，不再新增
- **侧边栏可收缩**：256px ↔ 64px（图标态，悬停有 tooltip），收起按钮在设置项上方，**或双击侧栏空白处切换**，状态持久化；收起后工作区多出约 190px
- 移除模式切换器后，侧边栏不再随页面变化
- `EpisodeDetail` 通过节目点击进入，提供明显的"返回节目列表"

### 3.2 页面存废清单

| 页面 | 路由 | 处置 |
|---|---|---|
| Dashboard | `/` | ✅ 保留，主入口（日历 + 统计） |
| EpisodeDetail | `/episode/:id` | ✅ 保留，核心工作台 |
| NewsPool | `/news-pool` | ✅ 保留 |
| Settings | `/settings` | ✅ 保留，tab 从 7 个收敛到 3 个 |
| EpisodeList | `/episodes` | 🗑️ 移除——功能与 Dashboard 重叠，批量删除能力并入 Dashboard |
| ScriptEditor / AudioStudio / Integration | `/scripts` `/audio` `/integration` | 🗑️ 移除——纯 mock，无任何导航入口（Issue #18） |

## 四、核心操作流设计

### 4.1 首次配置流（一次性，目标 ≤ 3 分钟）

```
首次进入 Dashboard（空状态）
  │
  ▼
空态引导卡："三步开始你的第一期节目"
  ① 配置 API Key  ② 添加 RSS 源  ③ 抓取新闻
  │
  ▼ 点 ① 跳转设置页 API 配置 tab
填入 DeepSeek Key + MiniMax Key → "保存并验证"
  │  ✅ 实时调用两家接口验证，显示连接状态徽章
  │  ⚠️ DeepSeek 需重启后端时，Toast 明确提示并提供"我已重启"确认
  ▼ 点 ② 跳转 RSS 源 tab
粘贴 URL → 自动解析标题 → 保存（或从"推荐源"一键添加）
  │
  ▼ 点 ③ 点击"抓取新闻"
抓取完成 Toast："已抓取 47 条新闻，已自动评分"
  │
  ▼ 返回 Dashboard，引导卡消失，出现"开始今日节目"按钮
```

**设计要点**：空状态即引导——用户第一次看到 Dashboard 时，日历区域替换为引导卡，完成后永久消失（完成后端配置检测：有 key + 有启用的源 + 有新闻）。

### 4.2 日常出片流（主流程，目标 ≤ 6 步）

```
Dashboard
  │
  │  步骤 1
  ▼
点击日历上的"＋"（或顶部"开始今日节目"）
  → 创建节目（默认标题"科技双响炮 · M月D日"，可改）并直接进入 EpisodeDetail
  → 若新闻池超过 6 小时未更新：后台自动触发抓取，右上角 Toast 提示"正在抓取最新新闻…"
  │
  │  步骤 2
  ▼
选料抽屉自动打开（全屏弹窗）
  → 按评分倒序展示今日新闻，默认已按 75+ 分过滤
  → 点击卡片勾选，右侧实时预览：N 条 · 约 X 字 · 预计 Y 分钟
  → 点"加入节目"（抽屉关闭，回到详情页）
  │
  │  步骤 3
  ▼
EpisodeDetail：检查列表顺序（拖拽微调）、（可选）给某条写备注
  │
  │  步骤 4
  ▼
点"生成逐字稿"（可选：先在节目备注框写一句本期要求）
  → 生成中：右栏显示骨架屏 + 阶段提示"正在阅读素材 / 撰写对话…（约需 30 秒）"
  │
  │  步骤 5（可选）
  ▼
通读逐字稿 → 点"编辑"inline 修改 → "保存"
  │
  │  步骤 6
  ▼
点"生成音频" → 进度条实时显示阶段与百分比
  → 完成 Toast + 播放器自动展开 → 试听
  → 满意：点"标记发布" → 状态变"已发布"，日历上显示 ✅
  → 不满意：修改逐字稿 → "重新生成音频"（或"删除音频"重来）
```

**对比现状的 5 处提效**：

| 现状断点 | 优化 |
|---|---|
| 抓取新闻要去设置页或新闻池 | 建节目时检测新鲜度，后台自动抓取 |
| 建节目和选料是两个独立动作 | 建节目后自动打开选料抽屉，且选完可直接生成 |
| 拖拽排序刷新后丢失 | 松手即调 reorder API 持久化（接口已存在，接上即可） |
| 节目备注刷新丢失 | 存入 episode（复用现有 `script_prompt` 字段或新增 `notes` 字段） |
| 没有"发布"出口，流程不闭环 | 音频完成后出现"标记发布"，写 `status` + `published_at` |

### 4.3 标题生成（AI 建议）

标题依赖内容——逐字稿出来后 AI 才有依据起名。设计如下：

1. **随稿产出，零额外等待**：逐字稿生成完成时，同一次生成顺带产出 3 条标题候选（真实后端为同次 LLM 调用输出）
2. **智能打扰**：
   - 标题仍是默认占位（`titleCustom = false`，如"科技双响炮 · 10月13日"）→ 标题下方自动滑出"AI 标题建议"面板（先显示"AI 正在构思标题…"，候选随后出现）
   - 用户已确认过标题（手动改过或采纳过建议）→ 不自动展开，标题旁 ✨ 按钮挂提示点
3. **采纳即所见**：点候选卡片 → 标题输入框立即更新 + Toast「已更新标题」+ 该候选打 ✓；面板内可"换一批"或"忽略"收起
4. **随时可用**：标题输入框右侧常驻 ✨ 按钮；无逐字稿时禁用，tooltip「生成逐字稿后，AI 可以推荐标题」
5. 候选带**风格标签**（观点型 / 悬念型 / 盘点型等），让选择有可感知的差异
6. 采纳建议同样视为标题已被确认（`titleCustom = true`），重新生成逐字稿时不再自动弹面板

### 4.4 图文正文（公众号）

公众号图文正文与逐字稿**共享中栏同一区块**，通过区块头部的 tab 切换（[ 逐字稿 | 图文正文 ]）：

1. **内容一次生成、两种渲染**：正文直接从素材撰写（与逐字稿相互独立），同一份 Markdown 内容源，可切换 **Markdown 视图**（渲染预览 + 编辑 + 复制，适配 mdnice 工作流）和**图片视图**（排版长图）
2. **图片正文 = 程序化排版长图**（非 AI 生图）：文字必须 100% 无乱码、版式可控；提供杂志风 / 卡片风两套模板，缩略图点选切换，点击大图灯箱查看全尺寸，下载 1.5x PNG
3. **Tab 状态可见**：另一侧正在生成时 tab 标签挂 spinner；正文生成完成后自动切到正文 tab 一次
4. 重新生成走"覆盖并生成"确认弹窗（与逐字稿一致）
5. 正式版实现：MD 正文由一个 LLM endpoint 产出（从素材直接写叙述稿）；长图渲染是纯前端 SVG + canvas，原型代码可直接复用

### 4.5 题图生成（社交发布素材）

题图用于公众号等社交平台发布，依据是**本期素材内容**，放在右栏"音频"之后（发布前的最后一块拼图）：

1. **按需生成，一次三版**：点击"生成题图"（约 5 秒，shimmer 占位 + "AI 正在构思画面…"）→ 一次产出 3 个风格变体（不同配色 + 版式：左对齐/居中/水印），横排缩略图
2. **选定制**：点选某版才算"本期题图"（coral 描边 + ✓ 角标）；未选定前大图预览第一版并标注"预览 · 点下方选一版"
3. **比例适配平台**：比例切换 chips——公众号头图 2.35:1 / 视频封面 16:9 / 次图 1:1，切换即时重渲染，不需要重新生成
4. **操作**：查看大图（灯箱）、换一批（已选定的题图保留，直到选中新版）、下载 PNG（2x 清晰度，直接可传公众号）
5. **准入条件**：至少有 1 条素材；无素材时按钮禁用并提示"先在左侧添加新闻"
6. 与标题建议的关系：标题建议随逐字稿**自动**产出（零成本顺带），题图**手动触发**（生成成本高、且并非每期都需要）——这是有意的差异

### 4.6 音频导出（发布到外部平台）

音频合成完成后，成品文件需要交付到公众号等外部平台：

1. **导出卡片**：音频区内、播放器下方常驻文件卡片——文件名（由节目标题生成，如 `科技双响炮-10月13日.mp3`）+ 时长 + 预估大小（MP3 128kbps ≈ 1MB/分钟）+ 格式
2. **一键导出**：点"导出音频"即下载成品文件，Toast「已开始下载」；卡片下方一行平台提示："可直接上传到公众号、小宇宙、喜马拉雅等平台"
3. **与"标记发布"的关系**：导出是把文件**拿到站外**（公众号后台手动上传）；标记发布是**站内**状态闭环。两者独立，不互相阻塞
4. 正式版实现零成本：后端已有 `/audio/{id}/episode_{id}.mp3` 静态服务，前端 `<a download>` 直链即可

### 4.7 纠错与恢复流

| 场景 | 设计 |
|---|---|
| 逐字稿生成失败 | 右栏显示错误卡："生成失败：{原因}"。按钮"重试"。素材与备注不丢失 |
| 音频合成失败 | 进度条变红，显示失败阶段；按钮"重新生成"。已生成的 splits 片段保留下次复用（待后端支持断点续传） |
| 误删节目内新闻 | 软删除 + Toast"已移除，可撤销"（5 秒内点撤销恢复原位置） |
| 误删节目 | 确认弹窗输入型确认（见文案体系）+ 后续可加回收站 |
| 中途关闭页面 | 重新进入时恢复：逐字稿/音频从数据库加载，音频生成中则恢复进度轮询 |

## 五、页面级设计

### 5.1 Dashboard（`/`）

**布局**：顶部统计条 → 月历主体。

- **统计**：不单设卡片，数字并入"全部节目"面板的状态过滤 tab（编辑中 N / 已发布 N 居左，全部 N 居右），点击即过滤，**默认聚焦"编辑中"**
- **日历格**：每天最多显示 2 条节目 + "+N"；节目块用状态色左边条（金色=编辑中，绿色=已发布）；点击进详情
- **全部节目面板**：日历右侧（宽屏并排，窄屏落到日历下方），按播出日期倒序列出所有节目，状态色点 + 日期 + 状态文字，可按状态过滤，点击直达详情——弥补日历只能逐月翻页、往期节目难找的问题
- **空状态**：首次使用显示"三步引导卡"；非首次但无节目时，日历上方显示"开始今日节目"主按钮
- **主操作**：右上角常驻珊瑚红主按钮"开始今日节目"

### 5.2 EpisodeDetail（`/episode/:id`）— 核心工作台

**布局**：左栏（400px）素材管理 + 右栏三段工作区（节目备注 / 逐字稿 / 音频）。

**左栏**：
- 顶部：返回按钮 + 标题/日期内联编辑（失焦保存，Toast"已保存"）
- 进度条：改为三阶段语义——素材 N 条 · 逐字稿 ✅/— · 音频 ✅/—（不再用 audio_done 条数这种用户看不懂的算法）
- 新闻卡片：序号 + 标题 + 状态徽章；展开可见正文、备注编辑、删除
- 拖拽排序：松手即保存（调用 reorder API），失败时回弹并 Toast 提示

**布局**：左栏（400px）——标题/日期/AI 标题建议/**节目备注**（紧凑折叠，失焦保存）/三阶段进度 + 素材列表；右侧工作区——**内容区（tab 容器：逐字稿 | 图文正文，详见 4.4）** / 音频 / 题图（详见 4.5）。**≥1600px 宽屏时自动切为「内容列 | 产出列」双列**：内容区在中列（约 1/2 宽，对话流形态下仍易读），音频+题图固定在右列（约 1.1 倍于内容列，sticky），滚动审稿时产出区始终可见；窄屏回退为单栏堆叠。

- **节目备注**：折叠面板，placeholder 提示用途（"本期想强调的角度，会随素材一起发给 AI"），失焦自动保存
- **逐字稿**：主按钮"生成逐字稿"（无素材时禁用并提示"先在左侧添加新闻"）；有稿后显示字数、"重新生成"和"编辑"；生成中显示骨架屏
- **音频**：主按钮"生成音频"（无逐字稿时禁用）；生成中显示进度条 + 阶段文案；完成后内嵌播放器 + "标记发布"主按钮 + "删除音频"次要按钮

**状态设计**：

| 状态 | 表现 |
|---|---|
| 空（无新闻） | 右栏逐字稿/音频区整体置灰，中央引导："先在左侧添加新闻" |
| 逐字稿生成中 | 骨架屏 + 阶段文案，按钮禁用，可正常操作左栏 |
| 音频生成中 | 进度条 + 阶段文案 + 百分比；离开页面再回来恢复轮询 |
| 生成失败 | 错误卡片（红）+ 原因 + "重试"按钮 |
| 完成 | 成功 Toast + 播放器自动展开 |

### 5.3 NewsPool（`/news-pool`）

- **顶部工具栏**：抓取按钮（显示"上次抓取：HH:mm"）、搜索框、评分过滤（全部/60+/75+/90+）
- **移除装饰性控件**：当前无效的排序下拉框直接删除，何时实现何时加回
- **来源筛选**：芯片多选，默认全选
- **卡片**：标题 + 来源 + 星级评分 + 日期 + 关键词（最多 3 个）；操作：👁 详情、☑ 选择
- **批量添加**：勾选后顶部浮条"已选 N 条 → 添加到节目"，点击弹出节目选择器
- **空状态**：无新闻时引导"先去抓取"（一键触发）；筛选无结果时提示"试试降低评分门槛"

### 5.4 Settings（`/settings`）— tab 从 7 收敛到 3

| Tab | 内容 | 说明 |
|---|---|---|
| RSS 源 | 源列表 + 增删改 + 启用开关 + 单源抓取 + 抓取全部 | 移除 auto_mode 开关 |
| API 配置 | DeepSeek / MiniMax key + 连接状态 + 保存并验证 | 保存时明确告知哪些配置需重启生效 |
| 提示词 | 系统提示词编辑 | **必须先修复后端不消费的问题**（Issue #24），否则 tab 不下线但标注"暂未生效"——不能让用户保存一个没用的东西 |

- 移除：主播配置、音色设置（音色硬编码在 `tts.py`，做成 UI 前先接后端）、定时任务、通知设置
- 顶部全局"保存设置"按钮移除——每个 tab 内自包含保存动作（消除"假保存"，Issue：设置页非 API tab 的保存只做动画）

## 六、状态与反馈设计

### 6.1 反馈层级（取代浏览器 alert/confirm）

| 层级 | 组件 | 用途 | 示例 |
|---|---|---|---|
| 轻量 | Toast（右上角，3 秒自动消失） | 保存成功、操作完成 | "已保存"、"已抓取 47 条新闻" |
| 中量 | Toast + 撤销（5 秒） | 可逆的删除 | "已移除该新闻 [撤销]" |
| 重量 | 确认弹窗 | 不可逆破坏 | 删除节目、删除音频 |
| 阻塞 | 页面内错误卡 | 生成失败等需现场处理 | "生成失败：API Key 无效 [重试]" |

### 6.2 耗时操作反馈标准

| 时长 | 反馈 |
|---|---|
| < 1s | 无需特殊反馈 |
| 1–5s | 按钮 loading 态 |
| 5–60s | 页面内进度区 + 阶段文案 + 预期时长提示 |
| > 60s | 进度条 + 百分比 + "可以离开，完成后回来查看"提示 |

### 6.3 加载与骨架

- 列表/日历加载：骨架屏（不用转圈 spinner）
- 提交类操作：按钮 loading + 禁用，防重复提交
- 网络错误：统一 Toast "网络异常，请检查后端服务是否运行"（不再只 console.error）

## 七、设计规范（在 DESIGN.md 配色基础上扩展）

### 7.1 配色（沿用 DESIGN.md，补充语义）

```
背景:   cream-100 #FDFBF7（页面）  cream-200 #F5F0E6（卡片/侧栏）
边框:   cream-300 #E8E0D0          hover: cream-400 #D4C9B5
文字:   ink-300 #2D2A24（主）       ink-50  #6B6659（次）
强调:   coral #E07A5F（主操作）     sage  #81B29A（成功/完成）
        gold  #D4A373（草稿/警告）   sky   #6CA0DC（进行中）
补充:   --      red #C4574E（破坏性操作/错误，从 coral 派生加深）
```

**语义规则**：coral 只用于"推进主线"的主按钮；red 只用于删除类；状态徽章用 sage/gold/sky/red 四色，与新闻状态一一对应。

### 7.2 字体与字号

```
字体栈: -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif
字号阶梯: 12(辅助) / 13(次要) / 14(正文) / 16(卡片标题) / 18(区块标题) / 24(页面标题) / 30(数字统计)
字重: 400 正文 / 500 强调 / 600 标题
行高: 正文 1.6，标题 1.3
```

### 7.3 间距与圆角

```
间距: 4px 基准 — 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48
圆角: 按钮/输入 12px，卡片 16px(rounded-2xl)，弹窗 24px(rounded-3xl)
阴影: 卡片 0 1px 3px rgba(45,42,36,.06)；弹窗 0 8px 30px rgba(45,42,36,.12)
```

### 7.4 动效

- 时长 150–250ms，ease-out；禁止超过 300ms 的动画
- 列表拖拽用 FLIP 平滑过渡；弹窗 fade + 轻微上浮（8px）
- Toast 从右上角滑入；页面切换不做转场动画（保持利落）
